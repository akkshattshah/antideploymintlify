Secrets are the secure way to store sensitive values your application needs — API keys, database passwords, OAuth tokens, signing keys, and any other credential you cannot afford to expose. Unlike environment variables, secrets are encrypted at rest, never displayed in plain text after you save them, and access to them is tracked in the audit log.

<Warning>
  Once you save a secret, its value is never shown again in the dashboard or via the CLI. Store the value somewhere safe before saving — if you lose it, you will need to rotate the secret with a new value.
</Warning>

## Secrets vs. environment variables

| | Environment Variables | Secrets |
|---|---|---|
| Encrypted at rest | No | Yes |
| Visible in dashboard | Yes | No (write-only after save) |
| Access logged | No | Yes |
| Suitable for credentials | No | Yes |
| Live reload support | Yes | No (requires redeploy) |

## Creating a secret from the dashboard

Open your app in the control center, navigate to **Configuration → Secrets**, and click **Add Secret**. Enter the key name and value, select the target environment, and click **Save**. The value is encrypted immediately and is not retrievable after this point.

## Managing secrets from the CLI

<CodeGroup>
```bash Create or update a secret
antideploy secrets set STRIPE_SECRET_KEY=sk_live_... --app my-app
```

```bash List secret names (values are never shown)
antideploy secrets list --app my-app
```

```bash Delete a secret
antideploy secrets delete STRIPE_SECRET_KEY --app my-app
```
</CodeGroup>

The `secrets list` command returns key names and metadata only — never values. This is intentional.

## How secrets are injected into your app

Secrets are injected into your app's runtime environment exactly like environment variables. Access them in your application code using the standard mechanism for your language:

```javascript
// Node.js
const stripeKey = process.env.STRIPE_SECRET_KEY;
```

```python
# Python
import os
stripe_key = os.environ.get("STRIPE_SECRET_KEY")
```

```go
// Go
stripeKey := os.Getenv("STRIPE_SECRET_KEY")
```

Secrets are never written to disk, never logged, and never included in build artifacts or container images. They are mounted at runtime only.

## Rotating a secret without downtime

When you need to update a secret — for example, to rotate an API key — Antideploy handles the transition without dropping traffic:

<Steps>
  <Step title="Set the new value">
    Run `antideploy secrets set MY_SECRET=new_value --app my-app` or update the value in the dashboard. The new value is encrypted and stored immediately.
  </Step>
  <Step title="Trigger a new deployment">
    Antideploy performs a rolling deployment — new instances come up with the new secret value before old instances are terminated. At no point is your app fully down.
  </Step>
  <Step title="Confirm and revoke the old credential">
    Once the deployment is complete and your app is healthy, revoke the old credential in the external system (e.g., your Stripe dashboard, your OAuth provider).
  </Step>
</Steps>

<Tip>
  Schedule secret rotation as a regular practice — quarterly at minimum for long-lived credentials. Use the audit log to track when each secret was last updated.
</Tip>

## Audit log

Every interaction with a secret is recorded in the audit log:

- Who created or updated the secret (user or API key)
- When the secret was accessed during a deployment
- Who deleted a secret and when
- Any failed access attempts

Access the audit log from **Settings → Audit Log** and filter by resource type **Secrets** to see a full history.
