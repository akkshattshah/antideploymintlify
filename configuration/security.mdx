Antideploy gives you layered controls over who can access your app, what they can do, and a complete audit trail of every action taken. Combine these controls with recommendations from App Intelligence to maintain a strong security posture as your team and application grow.

## Team roles

Every team member has a role that determines what they can see and do. Assign roles at the organization level or override them per app.

| Role | What they can do |
|---|---|
| **Owner** | Full access to everything: billing, team management, app deletion, all configuration |
| **Admin** | Everything except billing and organization deletion — can manage team members and all app settings |
| **Developer** | Deploy, configure, and manage apps — cannot invite team members or change roles |
| **Viewer** | Read-only access to dashboards, logs, and metrics — cannot make any changes |

## Inviting team members

<Steps>
  <Step title="Open team settings">
    Go to **Organization → Team** or open an individual app and navigate to **Settings → Access**. Click **Invite Member**.
  </Step>
  <Step title="Enter their email and select a role">
    Enter the team member's email address and select the role you want to assign. You can invite them at the organization level (applies to all apps) or scope the invite to a specific app.
  </Step>
  <Step title="Send the invite">
    Click **Send Invite**. The invitee receives an email with a link to accept. Their access is active the moment they accept.
  </Step>
</Steps>

<Note>
  Team members invited at the app level can only see and act on that specific app. They do not have visibility into other apps in your organization.
</Note>

## Deploy permissions

Control who can trigger sensitive operations on each app:

| Operation | Default minimum role | Configurable |
|---|---|---|
| Trigger a deployment | Developer | Yes |
| Trigger a rollback | Developer | Yes |
| Change environment variables | Developer | Yes |
| Modify secrets | Admin | Yes |
| Add or remove domains | Admin | Yes |
| Delete an app | Owner | No |

To change the minimum role required for an operation, go to **Settings → Permissions** in your app and adjust the role thresholds.

## API key scopes

When you create an API key under **Settings → API Keys**, you assign it a set of scopes that limit what it can do. Never create a key with broader access than needed.

| Scope | What it grants |
|---|---|
| `deploys:write` | Trigger and cancel deployments |
| `deploys:read` | Read deployment history and status |
| `config:write` | Update environment variables and settings |
| `config:read` | Read environment variable names and settings |
| `secrets:write` | Create and rotate secrets |
| `logs:read` | Stream and query application logs |
| `diagnostics:run` | Trigger App Intelligence diagnostic runs |

<Tip>
  Create separate API keys for each integration — your CI/CD pipeline, your monitoring stack, your on-call tooling. Scope each key to the minimum permissions it needs, so a compromised key has limited blast radius.
</Tip>

## Audit log

Every action taken in Antideploy is recorded in the audit log — by humans and by the AI. The log is append-only and cannot be modified or deleted.

Events captured include:

- Deployments triggered, completed, failed, or rolled back
- Configuration changes (environment variables, secrets, domains)
- Secret creation, rotation, and deletion
- Team member invitations, role changes, and removals
- API key creation and deletion
- App Intelligence diagnostic runs and applied fixes
- Login events and failed authentication attempts

Access the audit log from **Settings → Audit Log**. Filter by date range, actor, app, or event type. Export as JSON or CSV for compliance reporting.

## IP allowlisting

Restrict dashboard and API access to specific IP addresses or CIDR ranges to prevent access from unknown networks.

Enable IP allowlisting from **Organization → Security → IP Allowlist**. Add individual IPs or CIDR ranges (e.g., `203.0.113.0/24`). Once enabled, any request from an IP not on the allowlist is rejected with a 403 before reaching the dashboard.

<Warning>
  Before enabling IP allowlisting, make sure your own IP address is on the list. Locking yourself out requires a support request to recover access.
</Warning>

## Security recommendations from App Intelligence

App Intelligence continuously scans your app's configuration and behavior for security issues and surfaces them in the **Intelligence → Recommendations** panel. Common security findings include:

- Credentials or tokens detected in application logs
- Dependencies with known CVEs that have patches available
- Routes without authentication that appear to handle sensitive data
- Environment variables that look like secrets (based on naming patterns) rather than proper secrets

## Security best practices

- **Use Secrets, not env vars, for credentials.** Secrets are encrypted at rest and never displayed in plain text. See [Secrets](/configuration/secrets).
- **Enable two-factor authentication (2FA).** Require 2FA for your organization under **Organization → Security → Authentication Policy**.
- **Use scoped API keys.** Create a separate key per integration and grant only the scopes each integration needs.
- **Rotate credentials regularly.** Update secrets on a regular schedule and immediately if you suspect a key has been compromised.
- **Review the audit log periodically.** A weekly review of recent audit log entries helps you catch unexpected access or configuration changes early.
- **Keep dependencies updated.** App Intelligence will flag outdated dependencies with CVEs — prioritize these recommendations in your Reliability and Security queues.
