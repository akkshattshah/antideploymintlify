Antideploy ships an [MCP](https://modelcontextprotocol.io) server and an agent skill, so the agent that wrote your application can also deploy it. You ask for a change, and it edits the code, deploys, watches the build, and hands you back an address.

You do one thing: open a link and click Approve, once per machine.

<Note>
  No MCP? Paste one sentence into any coding agent that can read a web page and make web requests. It follows [a page that explains every step](https://antideploy.com/agent.md) and does the same work:

  ```text
  Set this project up to deploy on Antideploy. Fetch https://antideploy.com/agent.md and follow it.
  ```
</Note>

## Install

The server runs with `npx`, so there is nothing to install by hand. The first start downloads one package of about 250 kB.

<Tabs>
  <Tab title="Claude Code">
    The plugin installs the tools and the skill together.

    ```bash
    claude plugin marketplace add antideploy/antideploy-mcp
    claude plugin install antideploy@antideploy
    ```

    Start a new session. The plugin asks for nothing.

    To add only the tools:

    ```bash
    claude mcp add antideploy -- npx -y antideploy-mcp@0.2
    ```
  </Tab>

  <Tab title="Cursor">
    Open this link in a browser, or add the config below to `.cursor/mcp.json` (this project) or `~/.cursor/mcp.json` (every project).

    ```text
    cursor://anysphere.cursor-deeplink/mcp/install?name=antideploy&config=eyJjb21tYW5kIjoibnB4IiwiYXJncyI6WyIteSIsImFudGlkZXBsb3ktbWNwQDAuMiJdfQ==
    ```

    ```json
    {
      "mcpServers": {
        "antideploy": {
          "type": "stdio",
          "command": "npx",
          "args": ["-y", "antideploy-mcp@0.2"]
        }
      }
    }
    ```
  </Tab>

  <Tab title="Codex">
    ```bash
    codex mcp add antideploy -- npx -y antideploy-mcp@0.2
    ```

    Or add this to `~/.codex/config.toml`. Codex waits 10 seconds for a server to start by default, so raise the timeouts: the first start downloads the package.

    ```toml
    [mcp_servers.antideploy]
    command = "npx"
    args = ["-y", "antideploy-mcp@0.2"]
    startup_timeout_sec = 60
    tool_timeout_sec = 120
    ```
  </Tab>

  <Tab title="OpenCode">
    Add this to `opencode.json` in your project, or to `~/.config/opencode/opencode.json` for every project. OpenCode waits 5 seconds for a server's tools by default, so keep the longer `timeout`.

    ```json
    {
      "$schema": "https://opencode.ai/config.json",
      "mcp": {
        "antideploy": {
          "type": "local",
          "command": ["npx", "-y", "antideploy-mcp@0.2"],
          "enabled": true,
          "timeout": 60000
        }
      }
    }
    ```
  </Tab>

  <Tab title="Other clients">
    Any MCP client that can start a command: run `npx` with the arguments `-y antideploy-mcp@0.2`.

    ```json
    {
      "mcpServers": {
        "antideploy": { "command": "npx", "args": ["-y", "antideploy-mcp@0.2"] }
      }
    }
    ```
  </Tab>
</Tabs>

The configs pin `antideploy-mcp@0.2`, which takes every 0.2.x fix. To move to a new minor version, change that number.

## The skill

The `antideploy` skill tells the agent when Antideploy fits, how to connect, how to deploy, what to read when something fails, and when to use a different host instead. Claude Code, Cursor, Codex and OpenCode all read the same `SKILL.md` format.

The Claude Code plugin installs it for you. For the others, copy the folder [`skills/antideploy`](https://github.com/antideploy/antideploy-mcp/tree/main/skills/antideploy) from the repository to `.agents/skills/` in your project or `~/.agents/skills/` for every project; Cursor, Codex and OpenCode all look there. Keep the folder name `antideploy`.

## Your first deploy

<Steps>
  <Step title="Ask for it">
    In your agent, say what you want, for example **Deploy this project on Antideploy.**
  </Step>

  <Step title="Approve one link">
    The agent calls `login` and shows you a link and a short code. Open the link, check that the code matches, and click **Approve**. If you have no account, the same link creates one.
  </Step>

  <Step title="Let it finish">
    The agent creates the application for the folder, creates a Postgres database if the project needs one, deploys, and polls until the app is live. It tells you the address and which Antideploy account it went to.
  </Step>
</Steps>

Your login is saved in `~/.antideploy/config.json`, readable only by you. You can revoke it at any time on the [tokens page](https://antideploy.com/tokens).

## What the agent can do

| Group | Tools |
| --- | --- |
| Sign in | `login`, `logout` |
| Applications | `list_applications`, `create_application`, `link_application`, `check_address`, `app_settings`, `update_app_settings` |
| Deploy | `deploy`, `deployment_status`, `redeploy`, `rollback`, `deployment_history` |
| Variables | `list_env`, `set_env`, `set_env_from_file`, `remove_env`, `request_keys` |
| Run it | `logs`, `health`, `metrics`, and scheduled jobs |
| Database | `database_create`, `database_env_to_file`, `database_info` |
| Storage, sign-in and email for the app | `storage_create`, `auth_create`, `email_create` and their `*_env_to_file` and email management tools |
| Checks | `security_scan`, `security_scan_status` |

Deploys are asynchronous. `deploy` returns a task id, and the agent polls `deployment_status` until it reads `succeeded` or `failed`. Warnings and hazards in that answer are structured data meant to be read out to you.

Deleting an application or its database, custom domains and billing are not offered to agents. You do those in the [dashboard](https://antideploy.com/console).

## Files, secrets and keys

| File | What it is | Commit it? |
| --- | --- | --- |
| `~/.antideploy/config.json` | Your login. Outside your project | No |
| `.antideploy.json` | The application this folder belongs to. An id, no secret | Yes |
| `.env` | Database and other variables, if you asked for them. Added to `.gitignore` before it is written | No |

- **Tokens and passwords stay out of the conversation.** The tools that write `.env` answer with the variable names only.
- **A `.env` file is never uploaded.** To store variables from it, the agent calls `set_env_from_file` with the names it needs. It reads the file on your machine and sends only those. It refuses the names the platform sets itself, such as `DATABASE_URL`.
- **Keys only you have.** The agent calls `request_keys`, which gives you a page on antideploy.com to paste a Stripe key or a bot token into, so the agent never sees it.
- **A folder is tied to one application.** A folder without `.antideploy.json` is refused, never matched to an application by guesswork.

## Limits

The tools read the upload limits from the platform when they deploy, so they follow the API contract: currently 4,000 files and 28 MB for a project, and 28 MB for any one file. If a file is over the limit the agent is told which one, before anything uploads. One deploy at a time per application. A larger project can deploy from [GitHub](/deploying/github).

## Update and remove

In Claude Code:

```bash
claude plugin update antideploy@antideploy
claude plugin uninstall antideploy@antideploy
```

In Cursor, Codex and OpenCode, the config pins the version: change the number to update, and delete the `antideploy` entry (and the skill folder) to remove.

Removing the tools does not log you out. Delete `~/.antideploy/config.json`, or ask the agent to log out. To revoke the login on the server, use the [tokens page](https://antideploy.com/tokens).

## A project key, for a pipeline

For CI or a second machine, create a key for one application in the dashboard and set `ANTIDEPLOY_API_KEY` in the server's environment. The tools then work without `login`, bound to that application. Treat it like a password: it is built to survive being committed, but you should not publish it.

| Variable | |
| --- | --- |
| `ANTIDEPLOY_API_KEY` | Optional. A project key for one application. |
| `ANTIDEPLOY_URL` | Optional. Defaults to `https://antideploy.com`. |
| `ANTIDEPLOY_PROJECT_DIR` | Optional. The project folder, for a client that starts servers somewhere else. |

## Compared to the other ways in

| | Coding agent | [GitHub](/deploying/github) | [Upload](/deploying/upload) |
| --- | --- | --- | --- |
| Who triggers it | Your agent | A push to the default branch | You, in the dashboard |
| Needs a repository | No | Yes | No |
| Redeploys on push | No | Yes | No |
| Leaves the conversation | No | n/a | Yes |

## If something goes wrong

- **The tools do not appear.** Check that the server started: `claude mcp list` in Claude Code, `codex mcp list` in Codex, `opencode mcp list` in OpenCode. The first start needs a moment to download the package, and the server needs outbound HTTPS to antideploy.com.
- **The agent says it cannot reach antideploy.com.** Its sandbox blocks the domain. Allow it in the agent's network settings, or run the agent on your own machine.
- **A deploy failed.** The agent reads the reason and the logs, fixes the project and deploys again. See [Why did my deployment fail?](/guides/why-did-my-deployment-fail).
