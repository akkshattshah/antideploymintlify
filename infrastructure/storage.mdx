Any app that handles file uploads, stores media, or serves static assets needs object storage. Antideploy detects these patterns in your code and provisions a managed storage bucket automatically — no cloud console, no IAM policies, no bucket configuration required.

## What object storage is used for

Antideploy-managed storage handles a wide range of use cases:

- **User file uploads** — profile photos, documents, attachments
- **Media files** — images, videos, audio processed or served by your app
- **Generated files** — PDFs, exports, reports written by background jobs
- **Application backups** — database dumps or other data your app archives
- **Static assets** — JavaScript bundles, CSS, fonts, and images served to browsers

## Auto-detection and provisioning

Antideploy provisions a storage bucket when it detects any of the following in your codebase:

- An S3-compatible SDK dependency (`@aws-sdk/client-s3`, `boto3`, `minio`, etc.)
- File upload middleware (`multer`, `busboy`, `carrierwave`, `paperclip`, `active_storage`, etc.)
- Environment variable references to `STORAGE_URL`, `STORAGE_KEY`, or `STORAGE_SECRET`

The bucket is provisioned in the same region as your compute and linked to your app before the first deployment completes.

## Injected environment variables

Antideploy injects the following variables into your app's runtime environment automatically:

| Variable | Value |
|---|---|
| `STORAGE_URL` | The S3-compatible endpoint URL |
| `STORAGE_KEY` | Access key ID |
| `STORAGE_SECRET` | Secret access key |
| `STORAGE_BUCKET` | The name of your app's bucket |
| `STORAGE_REGION` | The region the bucket is deployed in |

You never hardcode these values or manage storage credentials manually.

## Accessing storage from your app

Your bucket exposes a fully S3-compatible API, so any S3 SDK works without modification. Point the SDK at `STORAGE_URL` and pass the injected credentials:

<CodeGroup>
```javascript Node.js (AWS SDK v3)
// STORAGE_URL and credentials are injected automatically
const { S3Client, PutObjectCommand, GetObjectCommand } = require('@aws-sdk/client-s3')

const s3 = new S3Client({
  endpoint: process.env.STORAGE_URL,
  region: process.env.STORAGE_REGION,
  credentials: {
    accessKeyId: process.env.STORAGE_KEY,
    secretAccessKey: process.env.STORAGE_SECRET
  },
  forcePathStyle: true
})

// Upload a file
async function uploadFile(key, body, contentType) {
  await s3.send(new PutObjectCommand({
    Bucket: process.env.STORAGE_BUCKET,
    Key: key,
    Body: body,
    ContentType: contentType
  }))
}
```

```python Python (boto3)
import os
import boto3

s3 = boto3.client(
    "s3",
    endpoint_url=os.environ["STORAGE_URL"],
    aws_access_key_id=os.environ["STORAGE_KEY"],
    aws_secret_access_key=os.environ["STORAGE_SECRET"],
    region_name=os.environ["STORAGE_REGION"]
)

# Upload a file
def upload_file(key, file_path, content_type):
    s3.upload_file(
        file_path,
        os.environ["STORAGE_BUCKET"],
        key,
        ExtraArgs={"ContentType": content_type}
    )
```

```javascript Node.js (multer-s3)
const multer = require('multer')
const multerS3 = require('multer-s3')
const { S3Client } = require('@aws-sdk/client-s3')

const s3 = new S3Client({
  endpoint: process.env.STORAGE_URL,
  region: process.env.STORAGE_REGION,
  credentials: {
    accessKeyId: process.env.STORAGE_KEY,
    secretAccessKey: process.env.STORAGE_SECRET
  },
  forcePathStyle: true
})

const upload = multer({
  storage: multerS3({
    s3,
    bucket: process.env.STORAGE_BUCKET,
    key: (req, file, cb) => cb(null, `uploads/${Date.now()}-${file.originalname}`)
  })
})
```
</CodeGroup>

## Public vs. private buckets

By default, every bucket is **private** — objects are not accessible without signed credentials. This is the right default for user uploads, sensitive documents, or any file that shouldn't be publicly reachable.

For files that should be publicly accessible (marketing assets, user avatars, publicly downloadable content), you have two options:

### Option 1: Public bucket

Enable public access for the entire bucket in **Infrastructure → Storage → Settings → Access**. Every object in the bucket becomes publicly readable at:

```
https://<bucket>.storage.antideploy.app/<key>
```

### Option 2: Per-object public access

Keep the bucket private and set `ACL: 'public-read'` on individual objects when you upload them:

```javascript
await s3.send(new PutObjectCommand({
  Bucket: process.env.STORAGE_BUCKET,
  Key: 'avatars/user-123.jpg',
  Body: imageBuffer,
  ContentType: 'image/jpeg',
  ACL: 'public-read'
}))
```

### Presigned URLs

For files in private buckets that you want to share temporarily, generate a presigned URL. The URL expires after a time you specify:

```javascript
const { getSignedUrl } = require('@aws-sdk/s3-request-presigner')

const url = await getSignedUrl(s3, new GetObjectCommand({
  Bucket: process.env.STORAGE_BUCKET,
  Key: 'reports/invoice-456.pdf'
}), { expiresIn: 3600 }) // URL valid for 1 hour
```

## CDN for static asset delivery

Antideploy automatically places a CDN in front of your public storage bucket. Files served through the CDN are cached at edge nodes close to your users, reducing latency and egress costs.

The CDN URL for your bucket is available as the `STORAGE_CDN_URL` environment variable. Use it instead of the raw bucket URL when generating public links to assets:

```javascript
const assetUrl = `${process.env.STORAGE_CDN_URL}/images/hero.jpg`
```

<Tip>
Use the CDN URL for all publicly served assets. The raw bucket URL bypasses the cache and incurs full egress costs for every request.
</Tip>

Cache invalidation happens automatically when you overwrite an object. To manually invalidate a path, use the CLI:

```bash
antideploy storage:invalidate --app my-app --path "/images/hero.jpg"
```

## Storage limits and pricing tiers

| Tier | Included storage | Included egress | Additional |
|---|---|---|---|
| **Starter** | 1 GB | 5 GB / month | $0.023 / GB stored, $0.09 / GB egress |
| **Basic** | 10 GB | 50 GB / month | $0.021 / GB stored, $0.08 / GB egress |
| **Standard** | 100 GB | 500 GB / month | $0.019 / GB stored, $0.07 / GB egress |
| **Professional** | 1 TB | Unlimited | $0.015 / GB stored |

To view current storage usage and costs, go to **Dashboard → Billing → Usage → Storage**.

<Note>
CDN egress is not counted against your outbound egress quota. Only direct bucket-to-client transfers consume your egress allowance.
</Note>

## Viewing your storage in the dashboard

Go to **Infrastructure → Storage** to see:

- Total storage used and object count
- Recent upload and download activity
- A file browser for navigating bucket contents
- Bucket settings (access policy, CDN, CORS configuration)
- Cost breakdown for the current billing period

You can upload, rename, delete, and download files directly from the dashboard's file browser without writing any code.
