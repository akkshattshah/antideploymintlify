The Model Context Protocol (MCP) is an open standard that lets AI coding assistants connect to external tools and services. Instead of switching to a terminal or dashboard, you can ask your AI to deploy your app, check logs, or roll back a broken release — and it executes the operation directly through Antideploy's MCP server.

## Supported tools

The Antideploy MCP server works with any MCP-compatible AI environment, including:

<CardGroup cols={3}>
  <Card title="Claude Code" icon="terminal" />
  <Card title="Cursor" icon="pen-to-square" />
  <Card title="Windsurf" icon="wind" />
</CardGroup>

If your tool supports MCP and lets you configure a custom server, Antideploy works with it.

## Get your API key

Before configuring MCP, generate an API key in the Antideploy dashboard under **Settings → API Keys**. Copy the key — you'll add it to your MCP config in the next step.

<Warning>
  Keep your API key out of source control. Store it in your MCP config file, not hardcoded in any file you commit to a repository.
</Warning>

## Set up the MCP server

Add the Antideploy server to your tool's MCP configuration file. The config location varies by tool:

<Tabs>
  <Tab title="Cursor">
    Edit or create `.cursor/mcp.json` at your project root (or `~/.cursor/mcp.json` for global config):

    ```json .cursor/mcp.json
    {
      "mcpServers": {
        "antideploy": {
          "command": "npx",
          "args": ["antideploy-mcp"],
          "env": {
            "ANTIDEPLOY_API_KEY": "your-api-key-here"
          }
        }
      }
    }
    ```
  </Tab>
  <Tab title="Claude Code">
    Add the server to your Claude Code MCP configuration file (`~/.claude/mcp.json` or the project-level equivalent):

    ```json mcp.json
    {
      "mcpServers": {
        "antideploy": {
          "command": "npx",
          "args": ["antideploy-mcp"],
          "env": {
            "ANTIDEPLOY_API_KEY": "your-api-key-here"
          }
        }
      }
    }
    ```
  </Tab>
  <Tab title="Windsurf">
    Edit `~/.windsurf/mcp_config.json`:

    ```json mcp_config.json
    {
      "mcpServers": {
        "antideploy": {
          "command": "npx",
          "args": ["antideploy-mcp"],
          "env": {
            "ANTIDEPLOY_API_KEY": "your-api-key-here"
          }
        }
      }
    }
    ```
  </Tab>
</Tabs>

After saving the config, restart your AI tool. It will launch the MCP server process automatically and make the Antideploy tools available in your conversation.

<Tip>
  The `npx antideploy-mcp` command fetches the latest server version on each start. You don't need to install anything separately — as long as Node.js is available, it works.
</Tip>

## Available MCP tools

Once connected, your AI assistant can invoke the following tools on your behalf.

<Accordion title="deploy_app">
Deploy the current project to Antideploy. The AI packages your code and kicks off a deployment, streaming progress back into the conversation.

**Parameters**
- `app_name` *(optional)* — override the app name inferred from the project
- `environment` *(optional)* — `production` or `staging` (default: `production`)
- `region` *(optional)* — target region for the deployment
</Accordion>

<Accordion title="get_logs">
Retrieve recent logs for a deployed app.

**Parameters**
- `app_name` *(required)* — name of the app
- `level` *(optional)* — filter by log level: `info`, `warn`, `error`, `debug`
- `since` *(optional)* — time window, e.g. `30m`, `1h`, `6h`
- `lines` *(optional)* — number of log lines to return (default: 100)
</Accordion>

<Accordion title="check_health">
Return the current health status of an app, including instance count, uptime, error rate, and any active health alerts.

**Parameters**
- `app_name` *(required)* — name of the app
- `environment` *(optional)* — environment to check
</Accordion>

<Accordion title="rollback_deployment">
Roll back an app to its previous successful deployment, or to a specific deployment ID.

**Parameters**
- `app_name` *(required)* — name of the app
- `deployment_id` *(optional)* — specific deployment to roll back to; defaults to the last successful deployment
- `environment` *(optional)* — environment to roll back
</Accordion>

<Accordion title="diagnose_app">
Trigger an AI-powered diagnostic and return a plain-language analysis of what's wrong, along with remediation suggestions.

**Parameters**
- `app_name` *(required)* — name of the app
</Accordion>

<Accordion title="list_apps">
List all applications in your Antideploy account, with their current status and environment URLs.

No required parameters.
</Accordion>

<Accordion title="get_metrics">
Fetch performance metrics for an app: request rate, error rate, p50/p95/p99 latency, CPU usage, and memory usage.

**Parameters**
- `app_name` *(required)* — name of the app
- `period` *(optional)* — time window: `1h`, `6h`, `24h`, `7d` (default: `1h`)
</Accordion>

<Accordion title="scale_app">
Adjust instance count and compute resources for an app. Changes take effect immediately without a new deployment.

**Parameters**
- `app_name` *(required)* — name of the app
- `min_instances` *(optional)* — minimum running instances
- `max_instances` *(optional)* — maximum instances under autoscaling
- `cpu` *(optional)* — vCPU count per instance
- `memory_mb` *(optional)* — memory per instance in MB
</Accordion>

## Example AI conversation

Here's what it looks like to use Antideploy through an AI assistant in Cursor after you've shipped a bad release:

> **You:** Something is wrong with my API — it started returning 500s about 20 minutes ago. Can you check?
>
> **Cursor:** I'll check the logs and health status now.
> *(calls `check_health` → app_name: "my-api")*
> *(calls `get_logs` → app_name: "my-api", level: "error", since: "30m")*
>
> Your app is showing a 34% error rate. The logs show `TypeError: Cannot read properties of undefined` in `src/handlers/users.ts` starting at 14:23 UTC — right after deployment `dep_b7c3f1a`. This looks like a bug introduced in the latest deploy.
>
> **You:** Roll it back.
>
> **Cursor:** Rolling back to the previous deployment now.
> *(calls `rollback_deployment` → app_name: "my-api")*
>
> Done. Traffic is now routed to `dep_9a1e4d2`. Error rate is dropping — down to 0.3% and falling.

## Security and permissions

The AI can only perform actions that your API key permits. Antideploy API keys support granular scopes — you can create a read-only key that allows `get_logs`, `check_health`, and `list_apps` but blocks `deploy_app`, `rollback_deployment`, and `scale_app`.

Manage your API key scopes in **Settings → API Keys**. Issue a least-privilege key for MCP if you want your AI assistant to have observability access but not the ability to change your production environment.
