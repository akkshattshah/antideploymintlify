The Antideploy CLI puts your entire deployment workflow on the command line. Deploy new versions, stream live logs, roll back a bad release, adjust scaling, and run AI-powered diagnostics — all without leaving your terminal or opening a browser.

## Installation

Install the CLI globally with your preferred package manager.

<CodeGroup>
```bash npm
npm install -g antideploy
```

```bash yarn
yarn global add antideploy
```

```bash pnpm
pnpm add -g antideploy
```
</CodeGroup>

## Log in

After installation, authenticate with your Antideploy account:

```bash
antideploy login
```

This opens your browser to complete OAuth authentication. Once you approve the login, the CLI stores a token locally and you're ready to go. The token is saved to `~/.antideploy/credentials` and refreshed automatically.

## Verify your installation

Confirm the CLI is installed correctly and your session is active:

```bash
antideploy --version
```

```bash
antideploy whoami
```

`whoami` prints your authenticated user and the active team, so you can verify you're operating under the right account before running any commands.

## Global flags

These flags work with every command and can be combined freely.

| Flag | Description |
|------|-------------|
| `--app <name>` | Target a specific app by name. Overrides the app inferred from `antideploy.yaml`. |
| `--env <production\|staging>` | Target a specific environment. Defaults to `production`. |
| `--json` | Output results as machine-readable JSON. Useful for scripting and CI pipelines. |
| `--help` | Print usage information for any command. |

## Configuration file

Place an `antideploy.yaml` file at your project root to set per-project defaults. This is optional — the CLI works without it — but it saves you from repeating flags on every command.

```yaml antideploy.yaml
app: my-api
env: production
region: us-east-1
```

Any value in `antideploy.yaml` can still be overridden by a flag at the command line. The resolution order is: **flag → environment variable → config file → CLI default**.

<Tip>
  Commit `antideploy.yaml` to your repository so every team member and CI job uses the same defaults automatically.
</Tip>

## Environment variables

You can also configure the CLI through environment variables, which is useful for CI/CD systems where you cannot store a config file.

| Variable | Description |
|----------|-------------|
| `ANTIDEPLOY_API_KEY` | API key for non-interactive authentication. Skips the browser login flow. |
| `ANTIDEPLOY_APP` | Default app name. Equivalent to `--app`. |
| `ANTIDEPLOY_ENV` | Default environment. Equivalent to `--env`. |
