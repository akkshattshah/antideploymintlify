Antideploy automatically provisions the infrastructure your app needs — compute instances, a managed database, and object storage. The Infrastructure API lets you inspect those resources, adjust compute scaling, and pull performance metrics for monitoring and autoscaling logic.

All infrastructure endpoints are scoped to a specific app. You need the app's ID to use them — retrieve it from the [Apps API](/api/apps).

---

## The infrastructure object

```json
{
  "compute": {
    "instances": 2,
    "min_instances": 1,
    "max_instances": 10,
    "cpu": 2,
    "memory_mb": 512
  },
  "database": {
    "provisioned": true,
    "tier": "starter",
    "connection_url": "postgres://..."
  },
  "storage": {
    "provisioned": true,
    "bucket": "my-api-prod",
    "region": "us-east-1"
  }
}
```

| Field | Type | Description |
|---|---|---|
| `compute.instances` | integer | Number of instances currently running. |
| `compute.min_instances` | integer | Minimum instances Antideploy will keep alive. |
| `compute.max_instances` | integer | Upper bound for autoscaling. |
| `compute.cpu` | integer | vCPUs allocated per instance. |
| `compute.memory_mb` | integer | Memory allocated per instance, in megabytes. |
| `database.provisioned` | boolean | Whether a managed database has been provisioned. |
| `database.tier` | string | Database tier: `starter`, `standard`, or `pro`. |
| `database.connection_url` | string | PostgreSQL connection string. Treat this as a secret. |
| `storage.provisioned` | boolean | Whether object storage has been provisioned. |
| `storage.bucket` | string | Name of the storage bucket. |
| `storage.region` | string | AWS region where the bucket is located. |

<Warning>
  The `database.connection_url` field contains credentials. Never log the infrastructure response or expose it to untrusted callers. Rotate your database credentials from the dashboard if you suspect exposure.
</Warning>

## Get infrastructure

```
GET /apps/{app_id}/infrastructure
```

Returns the current infrastructure configuration for an app, including compute, database, and storage details.

### Path parameters

<ParamField path="app_id" type="string" required>
  The unique ID of the app whose infrastructure you want to inspect.
</ParamField>

### Response fields

<ResponseField name="compute" type="object">
  Details of the compute layer for this app.
</ResponseField>

<ResponseField name="compute.instances" type="integer">
  Current number of running instances.
</ResponseField>

<ResponseField name="compute.min_instances" type="integer">
  Minimum instances configured for this app.
</ResponseField>

<ResponseField name="compute.max_instances" type="integer">
  Maximum instances this app can scale to.
</ResponseField>

<ResponseField name="compute.cpu" type="integer">
  vCPUs per instance.
</ResponseField>

<ResponseField name="compute.memory_mb" type="integer">
  Memory per instance in megabytes.
</ResponseField>

<ResponseField name="database" type="object">
  Managed database details. Fields are `null` if `provisioned` is `false`.
</ResponseField>

<ResponseField name="storage" type="object">
  Object storage details. Fields are `null` if `provisioned` is `false`.
</ResponseField>

### Example

```bash
curl -H "Authorization: Bearer $ANTIDEPLOY_API_KEY" \
  https://api.antideploy.io/v1/apps/app_abc123/infrastructure
```

```json
{
  "data": {
    "compute": {
      "instances": 2,
      "min_instances": 1,
      "max_instances": 10,
      "cpu": 2,
      "memory_mb": 512
    },
    "database": {
      "provisioned": true,
      "tier": "starter",
      "connection_url": "postgres://app_abc123:***@db.antideploy.io/app_abc123"
    },
    "storage": {
      "provisioned": true,
      "bucket": "my-api-prod",
      "region": "us-east-1"
    }
  },
  "error": null
}
```

## Scale compute

```
POST /apps/{app_id}/scale
```

Adjusts the compute resources for an app. Changes take effect immediately for scaling bounds (`min_instances`, `max_instances`). Changes to `cpu` or `memory_mb` trigger a rolling restart of all instances, which takes a few seconds.

### Path parameters

<ParamField path="app_id" type="string" required>
  The unique ID of the app to scale.
</ParamField>

### Request body

<ParamField body="min_instances" type="integer">
  Minimum number of instances to keep running. Must be at least `1`. Antideploy will never scale below this value.
</ParamField>

<ParamField body="max_instances" type="integer">
  Maximum number of instances to scale up to. Must be greater than or equal to `min_instances`. Antideploy scales within this bound based on traffic.
</ParamField>

<ParamField body="cpu" type="integer">
  Number of vCPUs to allocate per instance. Accepted values: `1`, `2`, `4`, `8`.
</ParamField>

<ParamField body="memory_mb" type="integer">
  Amount of memory in megabytes to allocate per instance. Accepted values: `256`, `512`, `1024`, `2048`, `4096`.
</ParamField>

### Response fields

<ResponseField name="compute" type="object">
  The updated compute configuration, reflecting the changes you requested.
</ResponseField>

### Example — scale out for a traffic spike

```bash
curl -X POST \
  -H "Authorization: Bearer $ANTIDEPLOY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "min_instances": 3,
    "max_instances": 20
  }' \
  https://api.antideploy.io/v1/apps/app_abc123/scale
```

### Example — upgrade instance size

```bash
curl -X POST \
  -H "Authorization: Bearer $ANTIDEPLOY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "cpu": 4,
    "memory_mb": 2048
  }' \
  https://api.antideploy.io/v1/apps/app_abc123/scale
```

```json
{
  "data": {
    "compute": {
      "instances": 3,
      "min_instances": 3,
      "max_instances": 20,
      "cpu": 4,
      "memory_mb": 2048
    }
  },
  "error": null
}
```

<Note>
  You only need to send the fields you want to change. Omitted fields keep their current values.
</Note>

## Get metrics

```
GET /apps/{app_id}/metrics
```

Returns performance metrics for an app over a specified time range. Use this to build dashboards, set up alerting, or drive custom autoscaling logic.

### Path parameters

<ParamField path="app_id" type="string" required>
  The unique ID of the app.
</ParamField>

### Query parameters

<ParamField query="metric" type="string" required>
  The metric to retrieve. One of:
  - `cpu_percent` — average CPU utilization across all instances
  - `memory_percent` — average memory utilization across all instances
  - `requests_per_second` — incoming HTTP request rate
  - `error_rate` — proportion of requests returning 5xx responses
  - `p99_latency_ms` — 99th percentile response latency in milliseconds
</ParamField>

<ParamField query="from" type="string" required>
  Start of the time range as an ISO 8601 timestamp (e.g., `2024-01-15T00:00:00Z`).
</ParamField>

<ParamField query="to" type="string" required>
  End of the time range as an ISO 8601 timestamp. Defaults to now if omitted.
</ParamField>

<ParamField query="resolution" type="string" default="1m">
  Granularity of data points. One of: `1m` (1 minute), `5m`, `1h`, `1d`. Coarser resolutions return fewer points and respond faster.
</ParamField>

### Response fields

<ResponseField name="metric" type="string">
  The metric name you requested.
</ResponseField>

<ResponseField name="from" type="string">
  ISO 8601 start of the returned data range.
</ResponseField>

<ResponseField name="to" type="string">
  ISO 8601 end of the returned data range.
</ResponseField>

<ResponseField name="resolution" type="string">
  Granularity of the returned data points.
</ResponseField>

<ResponseField name="points" type="array">
  Array of data point objects. Each has a `timestamp` (ISO 8601) and a `value` (number).
</ResponseField>

### Example

```bash
curl -H "Authorization: Bearer $ANTIDEPLOY_API_KEY" \
  "https://api.antideploy.io/v1/apps/app_abc123/metrics?metric=cpu_percent&from=2024-01-15T13:00:00Z&to=2024-01-15T14:00:00Z&resolution=5m"
```

```json
{
  "data": {
    "metric": "cpu_percent",
    "from": "2024-01-15T13:00:00Z",
    "to": "2024-01-15T14:00:00Z",
    "resolution": "5m",
    "points": [
      { "timestamp": "2024-01-15T13:00:00Z", "value": 18.4 },
      { "timestamp": "2024-01-15T13:05:00Z", "value": 22.1 },
      { "timestamp": "2024-01-15T13:10:00Z", "value": 64.7 },
      { "timestamp": "2024-01-15T13:15:00Z", "value": 71.3 },
      { "timestamp": "2024-01-15T13:20:00Z", "value": 45.0 }
    ]
  },
  "error": null
}
```

<Tip>
  Combine the metrics endpoint with the scale endpoint to build a simple autoscaling loop: poll `cpu_percent` every minute, and call `POST /scale` to adjust `min_instances` when utilization crosses a threshold.
</Tip>
